## 简介

本项目 `v3-ol-map` 是一个基于 Vue 3 和 OpenLayers 10 的地图组件库，旨在为开发者提供简洁、高效的地图集成方案。项目采用模块化设计，支持完整引入和按需引入，并通过解构 OpenLayers 的配置对象来简化 API 使用。

**重要更新**：项目已从传统的 Storybook 组件开发模式迁移至现代化的 VitePress + MDX 文档系统，提供更优质的文档体验和组件展示效果。

本贡献指南旨在为开发者提供清晰的参与路径，涵盖从环境搭建、代码规范、组件文档编写、测试到 Pull Request 提交的全流程说明。

## 项目结构

项目采用典型的 Vue 3 + Vite 构建结构，现已整合文档系统，主要目录如下：

- `src/examples`：存放各类地图功能的示例页面。
- `src/packages`：核心组件库源码，包含地图、图层、控件、交互等模块。
- `src/stories`：**已迁移** MDX 文档文件，用于组件的文档化和示例展示。
- `docs`：**新增** VitePress 文档系统，包含指南、组件文档和示例页面。
- `src/router`：路由配置。
- `src/App.vue` 和 `src/main.ts`：应用入口。
- 根目录下的 `package.json` 定义了项目依赖和脚本命令。

## 开发环境搭建

### 克隆代码仓库

首先，克隆项目到本地：

```bash
git clone https://github.com/pp129/v3-ol-map.git
cd v3-ol-map
```

### 安装依赖

项目使用 `pnpm` 作为包管理器。请确保已安装 `pnpm`，然后执行：

```bash
pnpm install
```

### 启动本地开发服务器

项目使用 Vite 作为开发服务器。启动命令如下：

```bash
pnpm dev
```

此命令会执行 `vite` 脚本，启动开发服务器，默认端口为 `8989`，并自动打开浏览器。

**新增**：同时支持文档系统的开发模式

```bash
pnpm docs:dev
```

该命令启动 VitePress 文档系统，默认端口为 `5173`，提供实时预览功能。

## 代码风格与提交规范

### 代码风格规范

项目采用 `ESLint` 和 `Prettier` 进行代码风格统一。

- **ESLint**：用于静态代码分析，检查潜在错误和代码质量问题。
- **Prettier**：用于代码格式化，确保代码风格一致。

相关配置在 `package.json` 中定义：

```json
"devDependencies": {
  "@typescript-eslint/eslint-plugin": "^7.11.0",
  "@typescript-eslint/parser": "^7.11.0",
  "eslint": "8.57.0",
  "eslint-config-prettier": "9.1.0",
  "eslint-plugin-prettier": "5.1.3",
  "eslint-plugin-vue": "^9.29.1",
  "prettier": "3.2.5"
}
```

### 代码检查与自动修复

- **运行 ESLint 检查**：
  ```bash
  pnpm lint
  ```
  此命令会检查 `src/packages` 目录下所有 `.vue` 和 `.ts` 文件。

- **自动修复可修复的问题**：
  ```bash
  pnpm fix
  ```
  此命令会在检查的同时尝试自动修复代码风格问题。

## VitePress 文档系统与 MDX 编写

### VitePress 文档系统概述

**重要更新**：项目已全面迁移到 VitePress + MDX 的现代化文档系统，提供更优质的文档体验。

VitePress 是一个基于 Vue 3 和 Vite 的静态站点生成器，专门用于构建文档网站。配合 MDX 支持，可以：

1. **组件化文档**：使用 Vue 组件渲染文档内容
2. **实时预览**：支持组件示例的实时交互预览
3. **主题定制**：提供丰富的主题配置选项
4. **SEO 友好**：生成优化的静态 HTML 页面

### MDX 文档编写规范

#### MDX 文件结构

MDX 文件结合了 Markdown 语法和 JSX 组件，支持在文档中直接嵌入 Vue 组件：

```mdx
import { Canvas, Meta, Controls } from "@storybook/blocks";
import * as OlConfig from "./OlConfig.stories";

<Meta of={OlConfig} />

# ol-config 配置组件

配置组件，用于为子组件提供配置上下文

## 全局配置

```js
// 全局配置示例
app.use(olMap, {
  tdt: {
    ak: "88e2f1d5ab64a7477a7361edd6b5f68a",
  },
  map: {
    view: {
      zoom: 10,
      center: [118.125827, 24.637526],
    },
  },
});
```

<Canvas of={OlConfig.Default} />

<Controls />
```

## 构建流程与类型生成

### 构建流程

项目提供了多种构建模式：

1. **生产环境构建 (production)**：
   ```bash
   pnpm build
   ```
   此命令执行 `vite build --mode production`，用于构建最终的应用。

2. **库模式构建 (lib)**：
   ```bash
   pnpm build:lib
   ```
   此命令是发布组件库的关键步骤，它会：
   - 执行 `vue-tsc` 进行 TypeScript 类型检查。
   - 执行 `vite build --mode lib`，根据 `vite.config.ts` 中的配置，将 `src/packages/index.ts` 作为入口，打包成 UMD 格式的库文件，输出到 `lib` 目录。

3. **文档构建**：
   ```bash
   pnpm docs:build
   ```
   此命令使用 VitePress 构建文档系统，生成静态网站文件。

4. **文档预览**：
   ```bash
   pnpm docs:preview
   ```
   预览构建后的文档网站。

### 生成类型声明文件

项目使用 `vite-plugin-dts` 插件来自动生成 `.d.ts` 类型声明文件。

- **配置**：在 `vite.config.ts` 的 `plugins` 数组中，`dts()` 插件被配置为扫描 `src/packages/**/*.{vue,ts}` 文件。
- **输出**：生成的类型声明文件会输出到 `es` 目录。
- **用途**：这些 `.d.ts` 文件对于使用 TypeScript 的用户至关重要，它们提供了组件的类型信息，实现智能提示和类型检查。

```ts
plugins: [
  vue(),
  dts({
    include: ["src/packages/**/*.{vue,ts}"],
    outDir: "es",
    tsconfigPath: "tsconfig.json",
  }),
],
```

## Pull Request 提交流程

### 分支命名

请遵循清晰的分支命名规范，例如：
- `feature/xxx`：用于新功能开发。
- `fix/xxx`：用于修复 bug。
- `docs/xxx`：用于文档更新。
- `chore/xxx`：用于构建脚本、依赖更新等维护性工作。

### 代码审查要求

1. **代码质量**：确保代码通过 `pnpm lint` 和 `pnpm fix` 检查。
2. **功能完整**：新功能或修复应包含必要的测试（如果项目有测试策略）和文档更新。
3. **代码注释**：对于复杂的逻辑，应添加必要的注释。
4. **文档更新**：如果修改了组件，应相应地更新或添加 VitePress 文档示例。
5. **兼容性**：确保修改不影响现有功能和 API。

### 合并标准

- **通过 CI/CD**：确保所有自动化测试和构建流程通过。
- **代码审查通过**：至少需要一位核心维护者批准。
- **分支同步**：在合并前，确保分支与 `main` 分支保持同步，避免冲突。
- **文档完整性**：新功能必须包含相应的文档更新。

### 提交规范

遵循 Conventional Commits 规范：

```bash
# 类型(scope): 描述信息

feat(storybook): 迁移配置组件文档到 MDX
fix(docs): 修复导航链接错误
docs(guide): 更新贡献指南文档
chore(build): 更新构建脚本
```

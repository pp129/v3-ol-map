## 简介

本指南旨在为使用 `v3-ol-map`（基于 Vue 3 和 OpenLayers 10）的开发者提供一套完整的故障排除方案。项目结构清晰，采用组件化设计，支持全局引入和按需引入两种方式。通过分析 `README.md` 和 `start.md` 文件可知，该库的设计理念是尽量贴近 OpenLayers 原生 API，通过 `props` 传递参数，并对复杂对象（如 `View`、`source`）进行解构以简化使用。

本文档将结合项目源码，针对地图容器渲染、图层加载、交互响应、坐标系统及性能问题等典型场景，提供详细的诊断步骤和解决方案。

## 常见问题与解决方案

### 地图容器未正确渲染

#### 问题描述
地图容器无法显示或显示为空白区域。

#### 可能原因
1. 容器缺少明确的宽度和高度
2. CSS 层级（z-index）被其他元素覆盖
3. 父级元素未设置尺寸或隐藏
4. 组件未正确挂载或初始化

#### 解决方案
确保地图容器具有明确的尺寸。推荐在 CSS 中设置：

```css
.ol-map-container {
  width: 100%;
  height: 500px;
  position: relative;
}
```

在模板中使用：

```vue
<template>
  <div class="ol-map-container">
    <ol-map :view="view">
      <ol-tile tile-type="OSM" />
    </ol-map>
  </div>
</template>
```

检查浏览器开发者工具中的 DOM 结构，确认 `.ol-map` 元素是否具有正确的宽高。若被遮挡，请调整 `z-index` 或检查父级元素的 `display` 属性。

## 图层加载失败

### 问题描述
瓦片图层、矢量图层或其他图层无法加载，控制台报错。

### 常见错误类型

#### 1. URL 错误或跨域问题
- **错误信息**：`Failed to load resource: net::ERR_FAILED` 或 `CORS error`
- **原因**：图层 URL 配置错误，或服务端未开启 CORS
- **解决方案**：
  - 检查 `source.url` 是否正确
  - 对于 TMS、WMS 等服务，确保协议（HTTP/HTTPS）匹配
  - 若为跨域问题，需服务端配置 `Access-Control-Allow-Origin`

示例（WMS 图层）：
```vue
<ol-wms :url="wmsUrl" :params="wmsParams" />
```

```ts
const wmsParams = {
  LAYERS: 'my_layer',
  TILED: true,
};
```

#### 2. 密钥缺失（如天地图）
- **原因**：TDTLayer 需要有效的密钥
- **解决方案**：在 `tile-type="TDT"` 时，确保 URL 包含 `tk=your_api_key`

```vue
<ol-tile tile-type="TDT" url="https://t0.tianditu.gov.cn/vec_c/wmts?tk=your_api_key" />
```

#### 3. 投影不匹配
- **原因**：图层数据投影与地图视图投影不一致
- **解决方案**：统一投影系统，如均使用 `EPSG:3857`

```ts
import { fromLonLat } from 'ol/proj';

const view = {
  center: fromLonLat([104, 30]),
  zoom: 10,
};
```

## 交互功能无响应

### 问题描述
绘制、测量、标注等交互功能点击无反应。

### 可能原因与解决方案

#### 1. 组件层级问题
- **原因**：交互组件未正确嵌套在 `<ol-map>` 内
- **解决方案**：确保交互组件作为 `<ol-map>` 的子组件

```vue
<ol-map>
  <ol-tile />
  <ol-draw type="Polygon" />
  <ol-measure type="line" />
</ol-map>
```

#### 2. 事件绑定错误
- **原因**：未正确监听交互事件
- **解决方案**：使用 `@drawend`、`@measureend` 等事件

```vue
<ol-draw @drawend="onDrawEnd" />
```

```ts
function onDrawEnd(event) {
  console.log('绘制完成:', event.feature);
}
```

#### 3. 功能未启用
- **原因**：某些交互功能需手动激活
- **解决方案**：检查组件是否默认启用，或通过 `active` prop 控制

```vue
<ol-draw :active="isDrawing" />
```

## 坐标显示异常

### 问题描述
鼠标位置显示坐标错误，或要素位置偏移。

### 原因分析

#### 1. 投影定义错误
- OpenLayers 默认使用 `EPSG:3857`（Web Mercator）
- 若数据为 `EPSG:4326`（经纬度），需进行转换

#### 解决方案
使用 `ol/proj` 模块进行坐标转换：

```ts
import { fromLonLat, toLonLat } from 'ol/proj';

// 经纬度转地图坐标
const mapCoordinate = fromLonLat([104.06, 30.67]);

// 地图坐标转经纬度
const lonLat = toLonLat(mapCoordinate);
```

在 `MousePosition` 控件中指定投影：

```vue
<ol-mouse-position :projection="EPSG:4326" />
```

```ts
import { register } from 'ol/proj/proj4';
import proj4 from 'proj4';

// 注册自定义投影
proj4.defs('EPSG:4490', '...');
register(proj4);
```

## 性能问题排查

### 问题描述
地图卡顿、缩放延迟、内存占用过高。

### 常见原因与优化建议

#### 1. 矢量数据量过大
- **现象**：加载 GeoJSON 或大量矢量要素时卡顿
- **优化方案**：
  - 使用 `VectorTile` 替代普通 `Vector` 图层
  - 启用 `WebGL` 渲染（`WebGLVector` 组件）
  - 添加要素聚类（`ol-cluster`）

```vue
<ol-cluster :distance="40">
  <ol-vector :features="largeFeatureSet" />
</ol-cluster>
```

#### 2. 图层过多或频繁重绘
- **建议**：
  - 合并静态图层
  - 使用 `groupLayer` 管理图层组
  - 关闭不必要的动画效果

#### 3. 内存泄漏
- **检查点**：
  - 确保在组件销毁时移除监听器
  - 避免全局变量持有地图引用
  - 使用 `map.dispose()` 正确释放资源

```ts
onBeforeUnmount(() => {
  mapRef.value?.dispose();
});
```

## 使用开发者工具进行调试

### 1. 检查网络请求
- 打开浏览器开发者工具 → Network 面板
- 查看图层瓦片、WMS 请求是否成功（状态码 200）
- 检查请求 URL 是否正确，参数是否完整

### 2. 查看控制台错误
- `Uncaught TypeError`：通常为参数类型错误或方法不存在
- `Projection not found`：投影未注册
- `Source is not defined`：图层 source 配置错误

### 3. 检查 DOM 结构
- 确认 `<ol-map>` 是否生成 `.ol-viewport` 容器
- 检查图层是否生成对应的 `<div class="ol-layer">`
- 验证控件（如缩放按钮）是否正确渲染

### 4. 调试 Vue 组件状态
- 使用 Vue Devtools 查看组件 props 和 events
- 检查 `view`、`source` 等对象是否正确传递

## 附录：已知问题与限制

根据 `README.md` 中的说明，当前版本存在以下限制：

### 参数解构不完整
- **问题**：部分 OpenLayers 类的 `Options` 未完全解构
- **表现**：某些 `props` 设置无效
- **临时方案**：直接访问底层 `ol` 实例进行配置

```ts
// 获取底层 ol.Map 实例
const mapInstance = olMapRef.value?.getMap();
// 直接调用 ol 方法
mapInstance.addLayer(new olLayer(...));
```

### 按需引入兼容性
- 确保构建工具（Vite/Webpack）正确解析 `.vue` 和 `.ts` 文件
- 若出现模块解析错误，检查 `tsconfig.json` 和 `vite.config.ts`

```ts
// vite.config.ts
export default defineConfig({
  resolve: {
    extensions: ['.ts', '.js', '.vue'],
  },
});
```
